# PRD R9 · 第一期（MVP）：恋爱局 + 取向机制满分 + 最小埋点

## 第一页 · MVP 一页纸（模板五问）

1. **服务谁**：20-30 岁城市年轻人的线下朋友局，一桌 3-6 人，男女混坐，有酒。核心用户 = 攒局的人。服务单位是**一桌**，不是一个人。
2. **核心假设 H1**：一桌 3+ 人的朋友局能不卡壳玩到亮相且愿意再开。口径：完局率 ≥60%；主开桌者 14 天复开率 ≥30%。
3. **北极星指标**：周完局桌数。日活是下游，不看。
4. **这期不做（负清单，全部关不删）**：图鉴/codex UI、满分人生入口、满分老板卡组、满分闺蜜卡组、展示柜赞评互动。题库内容零改动（Kim 明日 review）。UIUX 打磨归 Kim。不做圈层专属内容（SM 专题/黑话题库等二期看数据）。
5. **过闸**：本期仅两类活——让一桌人更玩得起来（取向机制、埋点）/ 保住招牌完整（亮相链路不动）。

定位（R8 已定，本期执行基准）：**满分男是一个酒桌游戏，它的摊牌是一场心理测试。** 版本确认：红弦俱乐部版（PRD-V2 像素赛博酒吧风，worker=ideal-type-loading）。老K 保留（品牌人格 + 取向采集入口，Kim 授权 PM 定夺）。

## 二、Kim 指出的致命逻辑错误（本期第一优先级）

> 「现在是由房主选择玩满分男还是玩满分女的，不由被拷问的人选择。被拷问的人的性别你又很难知道。」

现状：卡组（man/woman）是**桌级**选择，房主定了全桌的理想型性别。女同坐在满分男局里，整晚在给男人打分，亮相却出女性画像——题和人对不上。

## 三、取向架构方案（Fable 定稿）：题随被拷问者

### 3.1 核心原则：只问一件事

产品在机制层**只问每个人一个问题：「你想品鉴谁？」（seeking ∈ 男/女/都行）**，永不问玩家自己的性别/身份。直男、直女、男同、女同、跨性别在这套架构里不是五类用户，是同一个问题的三种答案——跨性别玩家无需任何特殊分支，天然被覆盖。这比「加一个男同版/直女版入口」更干净：没有版本、没有标签、没有柜门。

### 3.2 机制：满分男/满分女合并为一个「恋爱局」

- **开桌**：房主只选锅底（清汤/番茄/麻辣），不再选性别。首页 man/woman 两张卡合并为一张「满分男 · 满分女」。旧链接 man/woman 作为别名兼容，规整为 lover。
- **入座**：已注册玩家的 seeking 从档案带入（可在本桌临时改）；未注册散客在入座三连问（称呼/杯子/罚酒）后加第四问「想品鉴谁：男/女/都行」，一键完成。这就是 Kim 说的那个选择器，但它是**每人一份、私密语义、无圈层标签**。
- **抽题随被拷问者**：每轮题目按当轮主角（被拷问者）的 seeking 抽取与渲染——主角 seeking=男 → 全桌看「这是一个满分男，但他…」；=女 → 满分女她…；=都行 → 理想型TA…。你猜的是"小明的满分男"能不能被小明忍——这正是游戏的乐趣，也是机制修复本身。
- **亮相**：已按 seeking 出向（m→男/f→女/x→中性画像，R7 验证过），不动。

### 3.3 隔离做到满分：结构性零错配

- 题库池语义收紧：**共享轮换只从「视角中性池」抽**——任何对"打分者是谁"有假设的题（如默认打分者是女性的生理梗）一律不进轮换，直到 Kim review 后重标。配套交付《题库视角假设审计清单》（docs/QUESTION-AUDIT-R9.md）供 Kim 明日逐条定夺。错配不是"减少"，是**按构造不可能发生**。
- 主角 seeking 决定的只有目标性别文本（m/f/n 变体，题库 schema 天然支持，零内容改动）。
- 隐私：seeking 是玩家自我申报且随时可改（/u 档案 + 入座时）；不愿暴露方向的玩家选「都行」即得中性文本与中性画像。产品不外推、不存推断。

### 3.4 为什么这不是大手术

题库本就按锅底组织（qingtang/fanqie/zhongkou），每题自带 m/f/n 三版文本——man/woman 卡组只是渲染层薄壳。合并卡组 = 删壳，抽题过滤 = 换一个入参（deck→主角 seeking），亮相链路零改动。

## 五、最小埋点 + Kim 读数方案

- **事件**（六个，够 H1，不多埋）：room_created / player_joined / game_started / game_finished（=玩到亮相）/ poster_shared / register_done。带 {roomCode 哈希, deck, players, solo}。
- **存储**：新增 StatsDO（单例 Durable Object + SQLite，原子计数，KV 做不了原子所以不用 KV）；客户端 sendBeacon POST /api/track，失败静默不影响游戏。
- **读数**：GET /stats.html?key=<口令>（口令进 wrangler secret）出一页仪表盘：按日 开桌数/完局数/完局率/入座人数/海报分享数 + **周完局桌数大数字** + H1 达标线（完局率 60% 画一条线）。每个指标旁一句"这个数怎么读"。Kim 只需记住：**看周完局桌数涨不涨，看完局率过不过 60%。**
